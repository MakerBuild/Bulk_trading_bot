# Runtime dependencies -- the one list. install.bat installs from this file, so
# a version changed here is the version every operator gets on their next
# install or update. Do not add a second list anywhere else.
#
# Pinned exactly, to the versions the bot was last run and tested with. An
# unpinned install resolves to whatever PyPI has that day, so two operators who
# installed a week apart would be running different code under the same bot.
# To move a pin: change it here, reinstall, run the tests.
#
# These pins need 64-bit Python 3.12 or newer (numpy 2.5 is the floor; numba
# and llvmlite have no 32-bit Windows wheels). install.bat checks that before
# building the virtualenv.
#
# The SDK itself, bulk-client, is deliberately NOT in this file. install.bat
# installs it on its own, before this list, because it needs two things
# `pip install -r` cannot express:
#
#   * it comes from the wheel vendored in app/vendor (falling back to a pinned
#     GitHub commit only for a copy that predates the wheel). The build on PyPI
#     omits the trailing signature-domain byte the API requires, so every
#     signature it produces is rejected as "bad signature";
#   * it is installed with --no-deps. It declares bulk-keychain and solders,
#     imports neither, and bulk-keychain has no prebuilt wheel for current
#     Pythons, so pip would try to build it from Rust source and fail.
#
# Plain `pip install -r requirements.txt` is therefore not a complete install
# on its own. Use install.bat.

# Declared by bulk-client, listed here because --no-deps skips them. The bot
# never imports pandas, numpy or numba itself, but the SDK imports all three
# from `import bulk_api` (inventory, comparisons, the JIT order book), so none
# of them can be dropped while the SDK is.

# future requests can drop.
