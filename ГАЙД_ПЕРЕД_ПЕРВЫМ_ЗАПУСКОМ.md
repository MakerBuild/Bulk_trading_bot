# Установка с нуля

Для Windows 10 и 11. Если Python и git уже стоят — переходите сразу к шагу 3.

Весь путь занимает 10–15 минут, большая часть — ожидание скачивания.

---

## Шаг 1. Python

Нужен **64-битный** Python **3.12 или новее**. Старее не подойдёт: закреплённые
версии библиотек под него не собраны, и `install.bat` остановится с сообщением
`This needs 64-bit Python 3.12 or newer`. Сайт по умолчанию и так предлагает
64-битную версию.

1. Откройте **https://www.python.org/downloads/**
2. Нажмите жёлтую кнопку **Download Python 3.x.x** — сайт сам определит вашу систему
3. Запустите скачанный файл
4. **Внизу окна установщика поставьте галочку «Add python.exe to PATH».** Это самый важный шаг: без неё система не будет знать, где искать Python, и установка бота не начнётся
5. Нажмите **Install Now** и дождитесь конца
6. В конце может появиться кнопка **Disable path length limit** — нажмите её, если есть

**Проверка.** Нажмите `Win + R`, введите `cmd`, Enter. В чёрном окне наберите:

```
python --version
```

Должно ответить `Python 3.13.х` (или другая версия не ниже 3.12). Если пишет «не является внутренней или внешней командой» — галочку «Add to PATH» пропустили. Переустановите Python и поставьте её.

**Если на компьютере уже стоит Python старше 3.12, и другим программам нужен именно он** (менять его глобально нельзя): ставьте новый Python **без** галочки «Add python.exe to PATH», а галочку «py launcher» оставьте. `install.bat` сам найдёт новую версию через `py` и создаст окружение бота на ней, только в папке бота. Старый Python в PATH останется как был, `update.bat` тоже будет работать. Проверка в этом случае: `py -3.14 --version` вместо `python --version`.

## Шаг 2. Git

Нужен для обновлений: `update.bat` забирает новые версии именно через него.
`install.bat` тоже проверяет, что git стоит, и без него не начнёт. Сама
библиотека для работы с биржей лежит в папке бота и ничего не скачивает.

1. Откройте **https://git-scm.com/downloads**
2. Нажмите **Download for Windows** → **64-bit Git for Windows Setup**
3. Запустите файл и всю установку жмите **Next**, ничего не меняя — настройки по умолчанию подходят
4. В конце — **Install**, затем **Finish**

**Проверка.** Откройте **новое** окно `cmd` (старое не подхватит изменения) и наберите:

```
git --version
```

Должно ответить `git version 2.x.x`.

## Шаг 3. Установка бота

### Куда НЕ надо ставить

**Не на Рабочий стол, не в «Документы», не в «Изображения».**

Причина неочевидная. На свежих Windows при входе с учёткой Microsoft OneDrive
включает «Защиту важных папок» и **переносит сам Рабочий стол внутрь OneDrive**.
Проверить у себя: `Win + R` → `cmd` → Enter, затем

```
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders" /v Desktop
```

Если в ответе есть `OneDrive` — значит ваш Рабочий стол синхронизируется:

```
Desktop    REG_EXPAND_SZ    C:\Users\ВашеИмя\OneDrive\Desktop
```

Чем это плохо для бота:

- **Ваш приватный ключ уезжает на серверы Microsoft.** Он лежит в обычном
  текстовом файле в папке бота, а всё в синхронизируемой папке копируется в
  облако.
- **OneDrive держит файлы открытыми, пока выгружает их.** Бот пишет свой файл
  состояния во время работы, и живой прогон падал на `PermissionError` посреди
  цикла с открытыми позициями. В коде это вылечено, но причина остаётся.

### Куда надо

Любая папка вне синхронизации. Проще всего — прямо в вашей домашней:
`C:\Users\ВашеИмя\bulkdn`. OneDrive забирает только Рабочий стол, Документы и
Изображения, саму домашнюю папку он не трогает, и права туда есть всегда.

`C:\bulkdn` тоже годится, но в корень диска пишут не все учётные записи.

### Распакуйте архив

Правая кнопка по присланному ZIP → **«Извлечь все»** → укажите путь вида
`C:\Users\ВашеИмя\bulkdn`.

**Не запускайте бота прямо из ZIP.** Windows умеет показывать содержимое архива
как обычную папку, и `install.bat` оттуда вроде бы стартует — но всё, что он
создаст, пропадёт. Распакуйте по-настоящему.

Внутри должны оказаться `install.bat`, `run.bat`, `update.bat` и папка `app`.
Если вместо них одна вложенная папка — зайдите в неё, работать нужно с тем
уровнем, где лежит `install.bat`.

### Если уже поставили в синхронизируемую папку

Не страшно, но ключ стоит убрать из облака. Два пути, оба без переезда:

- **Зашифровать ключ**: `run.bat` → `4. Accounts Management` →
  `4. Encrypt Private Key`. В облако уедет зашифрованный блоб, бесполезный без
  пароля. Бот будет спрашивать пароль при запуске.
- **Или перенести папку**: закройте все окна бота, `move` её в `C:\bulkdn`,
  удалите `app\.venv` и запустите `install.bat` заново — пути к окружению
  зашиты внутрь его файлов, поэтому оно пересоздаётся.

### Дальше одинаково

Откройте папку и запустите **`install.bat`** двойным кликом.

Откроется чёрное окно и пойдёт установка. Она:
- создаёт локальное окружение в папке `app\.venv`
- ставит библиотеку BULK — она лежит в `app\vendor` и не качается из сети
- ставит остальные зависимости
- проверяет, что подпись транзакций работает

Это займёт несколько минут — качается около 200 МБ.

**Посреди установки появится красная надпись `ERROR`:**

```
ERROR: pip's dependency resolver does not currently take into account...
bulk-client 0.1.2 requires bulk-keychain>=0.1.5, which is not installed.
bulk-client 0.1.2 requires solders>=0.26.0, which is not installed.
```

**Это нормально, ничего не сломалось.** Библиотека BULK объявляет две
зависимости, которые сама никогда не использует. Они намеренно не ставятся:
одна из них не собирается на современных версиях Python и уронила бы установку.
Установщик предупреждает об этом строкой выше.

Смотреть надо не на эту надпись, а на последние строки:

```
  Signing check: OK

  Done. Next:
    1. Put your base58 private key on one line in private_key.local
    2. Edit settings.yaml -- the only settings file you touch
    3. Run run.bat
```

Если окно закрылось мгновенно и вы ничего не успели прочитать — запустите `install.bat` ещё раз, оно теперь дождётся нажатия клавиши.

## Шаг 4. Ключ

1. `install.bat` уже создал файл **`private_key.local`** в папке с ботом
2. Откройте его Блокнотом и вставьте приватный ключ вашего master-аккаунта BULK **под строками с `#`**, одной строкой, без кавычек. Если master-аккаунтов несколько — каждый ключ на своей строке
3. Сохраните (`Ctrl + S`) и закройте

Ключ никуда не отправляется — бот читает его только на вашем компьютере.

С одной оговоркой, которая от бота не зависит: если папка лежит в OneDrive,
Dropbox или Google Drive, **файл с ключом синхронизируется в облако** как любой
другой. Про это Шаг 3 — либо держите бота вне синхронизируемой папки, либо
зашифруйте ключ, как описано ниже.

**Сразу после первого запуска зашифруйте его:** в меню выберите `4. Accounts Management` → `Encrypt Private Key`. После этого в файле будет зашифрованный контейнер, а бот будет спрашивать пароль при старте.

**Придумайте настоящий пароль.** Если нажать Enter, ключ зашифруется константой,
которая лежит открытым текстом в исходниках бота — то есть открыть файл сможет
любой, у кого есть эта программа. Меню показывает, что именно у вас сейчас:

| | |
|---|---|
| `[PLAINTEXT]` | ключ лежит открытым |
| `[default password]` | зашифрован, но пустым паролем — защиты нет |
| `[encrypted]` | зашифрован настоящим паролем |

Ключ нужен только от master-аккаунта. У саб-аккаунта своего ключа нет — он создаётся и подписывается мастером, и бот находит все саб-аккаунты сам, при каждом запуске. В `settings.yaml` про саб-аккаунты ничего писать не нужно.

**Несколько ключей.** Каждый ключ из файла — это master со всеми его
саб-аккаунтами, и в режиме `mode: multi` (он стоит по умолчанию) все они
торгуют одним общим пулом. Порядок строк имеет значение: первый ключ — тот, с
которым по умолчанию работают команды `transfer` и `create-subaccount`, и тот,
чей аккаунт проверяется на реферала при старте; `single_master: 2` в режиме
`single` означает «ключ со второй строки».

**Все ключи вставляйте до шифрования.** Шифруется весь файл целиком, одним
контейнером, и зашифрованный файл Блокнотом уже не поправить. Если позже нужно
добавить ключ: `4. Accounts Management` → `5. Erase Local Data` → `2. Private key`
(файл очистится), вставьте **все** ключи заново и зашифруйте ещё раз. Сначала
убедитесь, что копии ключей у вас есть.

## Если BULK не открывается в вашей стране

**Большинству этот раздел не нужен — пропускайте.** Он про случай, когда биржа
заблокирована и бот не может подключиться.

Признаки: бот долго висит на запуске и падает с ошибкой подключения, при этом
`app.bulk.trade` не открывается и в браузере.

`install.bat` создал файл **`proxy.local`**. Впишите в него **одну строку** с
адресом прокси, без кавычек:

```
socks5h://user:password@proxy.example.com:1080
```

Подойдут `http://`, `https://`, `socks5://` и `socks5h://`.

**Просите у провайдера socks5h.** Буква `h` означает, что имя хоста
разрешает прокси, а не ваш компьютер. Там, где блокировка сделана через DNS,
именно локальный запрос имени падает первым — и обычный `socks5` не поможет.

Через прокси идёт **всё**: ордера, позиции, цены и поток аккаунта. Проверить,
что он подхватился, можно по первой строке лога при запуске:

```
routing every connection through socks5h://user:***@proxy.example.com:1080
```

Пароль в логах скрыт.

Пара вещей, о которых стоит знать:

- **Неправильный адрес останавливает бота сразу**, с объяснением. Это сделано
  нарочно: если бы кривую строку просто проигнорировали, бот пошёл бы напрямую,
  соединение бы не открылось, и выглядело бы это как «биржа лежит».
- **В файле обычно есть пароль.** Обращайтесь с ним как с ключом. Стирается он
  там же: `4. Accounts Management` → `5. Erase Local Data` → `6. Proxy`.
- Пока строка не вписана, файл ничего не меняет — можно просто оставить как есть.
- **Telegram-уведомления** (если настроены) идут через прокси, только если он
  `http://` или `https://`. SOCKS-прокси к ним не применяется — они уходят
  напрямую, и бот один раз пишет об этом в лог. Торговля при этом всё равно
  идёт через прокси.

## Шаг 5. Деньги на аккаунте

Бот не может создать аккаунт на бирже за вас.

1. Зайдите на **https://app.bulk.trade/** тем же кошельком, от которого дали ключ
2. Внесите USDC — этим создаётся торговый аккаунт
3. Запустите бота (`run.bat`) и выберите `4. Accounts Management` → `1. Create New Subaccount`. Бот спросит, у какого мастера (если ключей несколько), имя, и попросит подтвердить словом `yes` — удалить саб-аккаунт потом нельзя. В конце он пишет, что ответила биржа: создан, отказано или `NOT CONFIRMED` (сеть оборвалась, и неизвестно, дошёл ли запрос — проверьте, прежде чем создавать ещё раз)
4. Там же — `2. Balance All Subaccounts`, чтобы выровнять маржу между мастером и его саб-аккаунтами

**У каждого ключа должен быть хотя бы один саб-аккаунт**, иначе бот не
запустится с ошибкой `master ... has no sub-account`.

`Balance All Subaccounts` выравнивает деньги **внутри одного мастера**: перевод
подписывает ключ, которому принадлежат оба счёта, поэтому между разными
мастерами бот деньги не двигает. Если перевод оборвался на сети, он помечается
`UNKNOWN` — это значит «может быть, прошёл». Сначала посмотрите балансы, потом
повторяйте, иначе деньги могут уйти дважды.

**Сколько нужно денег.** Маржа на цикл считается так: `(нога₁ + нога₂) / плечо`.
При двух ногах по $100 и плече 10 это $20 — и столько должно быть **на каждом
счёте пула**, а не суммарно: открывающим может оказаться любой, поэтому бот
равняется на самый бедный. Размер из настроек берётся как есть, только если он
занимает не больше **80%** свободной маржи самого бедного счёта — в примере это
$25 на каждом. Если меньше, бот уменьшит все ноги так, чтобы цикл уложился в
`max_margin_fraction` (по умолчанию 25%) этой маржи, и напишет об этом в логе.
Держите запас: если во время входа цена уйдёт, хеджу может не хватить, и бот
остановится.

Отдельно про минимальный размер: биржа не принимает ордер дешевле своего порога
— $1 у BTC-USD, $50 у ETH-USD и SOL-USD. Поэтому нога меньше $50 в ETH просто
не откроется, сколько бы денег ни лежало на счёте.

## Шаг 6. Настройки

Откройте **`settings.yaml`** Блокнотом. Всё, что обычно меняют, — в верхней половине:

| Строка | Что означает |
|---|---|
| `mode:` | какие аккаунты торгуют: `multi` — все ключи и все их саб-аккаунты, `single` — один мастер и его саб-аккаунты |
| `max_groups:` | сколько групп торгуют одновременно |
| `max_takers:` | на сколько аккаунтов делится один хедж (1 — не делится) |
| `enabled:` | торгуется ли этот рынок |
| `symbol:` | какая пара торгуется |
| `notional_usd:` | на какую сумму в долларах набирать за цикл |
| `leverage:` | плечо |
| `hold_minutes:` | сколько минут держать позицию открытой (можно диапазон, `0.5-1`) |
| `burn_usd:` | сколько комиссий сжечь **за один прогон**, потом остановиться |
| `max_phase_minutes:` | через сколько минут считать вход или выход зависшим |
| `offset_bps:` | насколько ордер стоит внутрь от лучшей цены |
| `chase_patience_s:` | через сколько секунд без исполнения идти к рынку |
| `improve_ticks:` | на сколько тиков встать впереди лучшей цены (1 = быть лучшим бидом) |
| `join_depth_usd:` | вместо этого вставать в очередь туда, где уже стоит объём чужих ордеров (0 = выключено) |

**`burn_usd` считается от начала прогона, а не за всю жизнь счёта.** Нажали
Start — счёт с нуля. Дошёл до `burn_usd` — остановился. Нажали Start снова —
снова с нуля. То, что вы сожгли вчера, сегодняшний прогон не заканчивает.

Если прогон прервали (нажали `S`, упало, сработал предохранитель) — при
следующем запуске счёт **продолжится**, а не начнётся заново: то, что уже
оплачено, не возвращают. Начать цель заново осознанно — `run.bat flatten --live`
или пункт `6. Close All Positions`, они сбрасывают точку отсчёта.

Посмотреть, где вы сейчас: пункт `5. Configuration` → Progress. Там две
колонки — за всё время и за текущий прогон.

Размер задаётся **в долларах**, а не в монете: `notional_usd: 100` — это $100
и в BTC, и в ETH. Бот сам пересчитает в количество по текущей цене при запуске.
Поэтому пару можно поменять, не пересчитывая цифру.

Старый вариант `size:` (количество монеты) тоже работает, но он привязан к цене
одной монеты: `size: 2.0` — это $200 в SOL и $5,200 в ETH. В одной ноге должно
стоять либо `notional_usd:`, либо `size:`, но не оба сразу.

Начните с малых размеров. Биржа не примет ордер меньше $1 по BTC и меньше $50 по ETH.

**Как бот торгует пулом.** Каждый цикл он собирает **группу**: один аккаунт
ставит лимитный ордер, один или несколько других хеджируют каждое его
исполнение по рынку, в долях, выбранных при сборке группы. Когда цикл
закончен, группа распадается, а следующая собирается заново — аккаунты,
рынок, размер выбираются снова. Один аккаунт одновременно бывает только в
одной группе. `cycles` в `execution_target` считает, сколько групп запущено за
прогон.

**Опечатки в настройках бот не пропускает молча.** Неизвестная строка — это
предупреждение в логе с подсказкой, какая настоящая похожа
(`did you mean ...`). Число, записанное с ошибкой, или `true/false` не там —
это остановка с названием строки. Если бот пишет `is not saved as UTF-8` —
Блокнот сохранил файл в другой кодировке: `Файл` → `Сохранить как`, внизу
«Кодировка» — `UTF-8`, сохранить.

### Как бот набирает позицию

Он **не бьёт по рынку**, а ставит лимитный ордер и ждёт. Это дешевле: пассивное
исполнение на BULK бесплатное (`makerFee: 0.0`), комиссию берут только с
тейкерской стороны хеджа. Поэтому комиссия набегает медленно — в `burn progress`
попадает почти только хедж.

Плата за дешевизну — ожидание. Бот работает в две стадии:

| | |
|---|---|
| `offset_bps: 2.0` | сначала ордер стоит на 0.02% внутрь от лучшей цены и ждёт, пока рынок сам до него дойдёт |
| `chase_patience_s: 3` | не исполнился за 3 секунды — хватит ждать, идём к рынку |
| `improve_ticks: 1` | и встаём **на один тик впереди лучшей цены** |

Третья строка — самое важное для скорости. Встать *на* лучшую цену означает
занять очередь позади всех, кто уже там стоит, и исполниться после них. Встать
на тик лучше — значит стать лучшим бидом (или аском) и исполниться первым.

Живой пример на BTC:

```
стакан:  bid 76 709.0   ask 76 710.0

было:  покупка 76 709.0   <- в очередь, ждём всех впереди
стало: покупка 76 709.5   <- очередь пустая, мы первые
```

**Тейкером бот не становится.** Цена всегда остаётся строго внутри спреда: если
спред всего один тик, вставать некуда, и ордер просто стоит на лучшей цене.
Комиссия мейкерская в любом случае — платим тиком цены, а не комиссией.

Дальше ордер держится переднего края **по тикам**: сдвинулся стакан — ордер
переставляется следом. Если стакан не двигается, не отправляется ничего.

Что крутить:

- Быстрее исполняться — уменьшить `chase_patience_s` (до 1–2) или `offset_bps`.
- Экономнее, но медленнее — `improve_ticks: 0` (встать в очередь) и больше
  `chase_patience_s`.
- Ещё экономнее — `join_depth_usd: 2000`: ордер встаёт только на цену, где уже
  стоят чужие ордера минимум на $2 000 (не дальше 0.01% от лучшей цены), и
  уходит оттуда, если они разошлись. Почему это важно: когда наш ордер стоит на
  цене один, его исполнение опустошает этот уровень, и хедж проходит уже по
  следующему — на живых данных в среднем на 1.6 bps хуже. Когда рядом стоит
  объём, хедж проходит по нашей же цене. Исполняться в очереди дольше.

Цена скорости — ордер чаще переставляется, а каждая перестановка это транзакция.
Чаще одного раза в `chase_interval_s` (1 секунда) этого не происходит.

В логе подтяжка выглядит так:

```
BTC-USD replaced BUY 0.001294 @ 77262.442 on m1
        [unfilled for 8s -- moving onto the touch from 2bps inside]
```

## Шаг 7. Запуск

Запустите **`run.bat`**. Откроется меню:

```
1. Start                  начать торговлю
2. Active Strategy        что открыто сейчас
3. History                прошлые сделки
4. Accounts Management    саб-аккаунты, балансы, ключ, удаление данных
5. Configuration          цели, рынки и аккаунты, прогресс
6. Close All Positions    отменить всё и закрыть позиции
7. Logs                   конец logs.txt и путь к файлу
0. Exit                   выйти
```

`Ctrl+C` на любом вопросе меню отменяет действие: ничего не сохраняется и не
отправляется, вы возвращаетесь в главное меню.

Перед первой торговлей проверьте настройку. Если `run.bat` запущен двойным
кликом, окно закроется вместе с меню, поэтому откройте отдельное: зайдите в
папку бота, наберите `cmd` в адресной строке проводника, Enter, и в
открывшемся окне:

```
run.bat check
```

Это ничего не торгует, только проверяет, что ключ читается, аккаунты найдены и у мастера есть саб-аккаунт.

## Шаг 8. Как останавливать

Это самое важное место в гайде, прочитайте до запуска.

### Нажмите `S`

Пока бот работает, в окне висит рамка:

```
  +-----------------------------------------------------------+
  |  S  -- stop and cancel                                    |
  +-----------------------------------------------------------+
```

Нажмите **S** прямо в этом окне — ничего открывать и закрывать не нужно.
Напоминание продублировано в заголовке окна (`bulkdn [3/10] HOLD -- S = stop`),
так что оно не потеряется, даже когда рамку утянет наверх логами.

Что произойдёт: все группы дойдут до конца текущего шага (около секунды), все
висящие ордера будут сняты, бот ещё раз прочитает позиции и захеджирует то,
что успело исполниться, пока ордера снимались, в лог запишется, что именно
осталось открытым, и вы вернётесь в меню. **Позиции при этом не закрываются** — они остаются как есть,
захеджированные. Закрыть их — пункт `6. Close All Positions`.

Нажать `S` можно в любой момент: бот не бросает ордер на полпути, а доводит
текущий шаг до конца и только потом останавливается.

### Как закрывать: по рынку или лимиткой

Пункт `6. Close All Positions` предлагает три варианта:

```
  1. dry run       показать, что будет отправлено, ничего не отправляя
  2. market close  по рынку: сразу, но вы платите спред и тейкерскую комиссию
  3. limit close   лимиткой: без тейкерской комиссии, но нужно ждать
```

Оба живых варианта работают **только на уменьшение** — открыть новую позицию
они не могут физически, даже если данные о позиции устарели.

**`2. market close`** — закрывает за секунды. Берите его, когда важнее выйти,
чем цена: вы уходите в минус на спред плюс тейкерская комиссия с каждой
единицы.

**`3. limit close`** — ставит ордер на лучшую цену в стакане (на тик лучше
лучшей цены, чтобы стоять первым в очереди) и переставляет его, когда рынок
уходит. Ордер никогда не переходит на другую сторону, поэтому исполнение всегда
мейкерское и тейкерской комиссии нет. Плата за это — ожидание: ордер исполнится
только тогда, когда кто-то захочет с ним торговать.

Через **5 минут**, если закрыть не удалось, бот снимает свои ордера, пишет в
лог, что осталось открытым, и возвращает вас в меню. Позиция при этом остаётся
открытой — это не ошибка, а честный отчёт. Дальше решаете вы: запустить limit
close ещё раз или закрыть по рынку.

`Ctrl+C` во время limit close тоже снимает выставленные ордера и возвращает
в меню — брошенных ордеров на бирже не останется.

**Что выбирать.** Если позиция вам не мешает и вы никуда не спешите — `3`,
он дешевле. Если нужно быть плоским прямо сейчас (уезжаете, закрываете
терминал, что-то пошло не так) — `2`, не экономьте на спреде.

### Чего делать не надо

**Ctrl+C и крестик окна НЕ закрывают позиции.** Они только отключают бота. Ваши
лимитные ордера остаются жить на бирже и могут исполниться — а хеджировать их
уже некому. Из дельта-нейтральной пары получается односторонняя позиция без
присмотра. Прервать бота в середине входа — худшее, что можно сделать.

Теперь для этого нет причин: `S` делает то же самое, но аккуратно.

### Если всё-таки прервали или окно закрылось

1. Откройте окно в папке бота и выполните:

   ```
   run.bat flatten --live
   ```

   Она снимает все ордера, закрывает позиции по рынку на всех аккаунтах и
   на всех рынках из `settings.yaml`, включая выключенные (только на
   уменьшение — открыть новую она не может физически), и сбрасывает
   состояние. **Подтверждения не спрашивает** — срабатывает сразу. Если на
   аккаунтах осталась позиция на рынке, которого в `settings.yaml` нет,
   команда назовёт её и состояние не сбросит: такую позицию закройте на
   бирже вручную.

2. **Дождитесь, пока команда отработает.**

То же самое делает пункт `6. Close All Positions` → `2. market close`, если бот
стоит в меню и ничего не делает. Там же есть `3. limit close` — дешевле, но
ждёт; после аварийного обрыва обычно нужен именно `2`, чтобы не оставлять
незахеджированную позицию висеть.

Если `flatten` почему-то не отрабатывает — зайдите на bulk.trade и закройте
позиции руками на всех счетах — у каждого мастера и всех его саб-аккаунтов.
Ордера тоже снимите везде.

### Если уже закрыли окно

Ничего страшного, но **проверьте прямо сейчас**, а не при следующем запуске.
Запустите `run.bat`, пункт `2. Active Strategy` — он покажет, что осталось
открытым. Если фаза не `IDLE` или видны ордера:

```
run.bat flatten --live
```

Отработает вхолостую за секунды, если висеть нечего. Стоит выполнять всегда,
когда бот завершился не сам, а был прерван.

## Шаг 9. Если бот сам остановился

У бота есть предохранители: слишком большая односторонняя экспозиция, слишком
крупная позиция, несколько отказов биржи подряд, пропавшие котировки, а также
вход или выход, который не завершился за `max_phase_minutes` — это ловит
случай, когда лимитный ордер просто некому исполнить. В режиме multi такой
вход или выход не останавливает весь прогон: обрезается только эта группа
(вход оставляет то, что успел набрать, выход докрывает остаток по рынку),
а остальные торгуют дальше. Бот остановится, только если и после этого
группа не закрылась за 5 минут. Экспозиция проверяется
и по всем счетам вместе, и по каждой группе отдельно. Позиция, закрытая
кем-то снаружи (например, ликвидация), тоже останавливает бота: он перестаёт
хеджировать, закрывает этот рынок на всех счетах и записывает остановку. Любой
из предохранителей останавливает торговлю, закрывает позиции и записывает
причину.

Если бот упал по любой другой причине (ошибка, обрыв), он всё равно сначала
снимает все висящие ордера, а в лог пишет, что осталось открытым. Позиции в
этом случае не закрываются — проверьте `2. Active Strategy`.

При следующем запуске вы увидите:

```
state file records a halt: reject_streak: sub1 has 5 consecutive rejected
transactions -- last was REJECTED_INVALID: ...
```

**Сначала прочитайте причину** — она там написана целиком, вместе с ответом
биржи. Висящие ордера бот при этом уже снял. Это и есть смысл остановки: понять, что случилось, прежде чем
продолжать.

Затем снимите остановку:

```
run.bat flatten --live
```

Она же и закроет позиции, если что-то осталось открытым. Файл состояния
удалять руками не нужно.

## Где смотреть логи

В папке бота лежит **`logs.txt`** — туда пишется всё то же самое, что бежит в
окне. Файл появляется при первом запуске и дописывается при каждом следующем.

Он нужен ровно для одного: окно можно закрыть, промотать или потерять, а файл
остаётся. Если бот ночью остановился, а вы утром видите пустое окно — ответ
будет там.

Быстро посмотреть последние строки, не открывая файл: `run.bat` → пункт
`7. Logs`. Там же напечатан полный путь к файлу — его удобно скопировать, если
просят прислать логи.

Что искать:

| строка | что значит |
|---|---|
| `=== g3:BTC-USD HOLD: 1.2 minutes ===` | группа 3 вошла и держит |
| `stop requested (keyboard)` | вы нажали `S` |
| `BTC-USD left open (g3:BTC-USD HOLD): ...` | что осталось на момент остановки |
| `halted: ...` | сработал предохранитель, причина рядом |
| `could not verify referral` | индексер BULK не ответил, см. ниже |

Файл сам себя ограничивает: доходит до 5 МБ, переименовывается в `logs.txt.1`,
и начинается новый. Старее двух таких файлов ничего не хранится, забить диск
он не может. Удалять его можно, когда бот закрыт. Пока окно бота открыто,
Windows держит файл занятым и удалить его не даст — закройте бота, потом
удаляйте.

## Как обновляться

Когда выйдет новая версия, запустите **`update.bat`** двойным кликом. Всё.

Он скачает свежую версию и заменит файлы программы. **Ваши настройки и ключ не
трогаются** — и не потому, что они перечислены в списке исключений, а потому,
что их нет в том, что скачивает `update.bat`: перезаписывать их просто нечем.

| остаётся вашим | заменяется |
|---|---|
| `settings.yaml` | `app\` — код бота |
| `private_key.local`, `proxy.local` | `run.bat`, `install.bat` |
| `app\state` — что открыто | `app\settings.default.yaml` — образец настроек |
| `app\.venv` — окружение Python | документация |
| `logs.txt` — история запусков | |

**Перед обновлением остановите бота.** Если он торгует — сначала закройте
позиции (`run.bat flatten --live`), потом обновляйтесь.

Пара мелочей, чтобы не удивляться:

- **`app\settings.default.yaml` может получить новые настройки.** Это образец,
  из которого `install.bat` когда-то сделал ваш `settings.yaml`. Бот его не
  читает и обновление его перезаписывает — ваш `settings.yaml` при этом не
  меняется. Если в образце появилось что-то полезное — перенесите строку руками.
- **`update.bat` обновляет и сам себя.** Архив внутри устроен как клон
  репозитория, поэтому обновление — это слияние, и оно заменяет все файлы
  разом. У архивов, разосланных до 19 сентября, это было не так: они
  копировали файлы поверх, а копировать `.bat` поверх работающего нельзя —
  Windows читает его с диска по мере выполнения, и на месте подменённых байтов
  начинается бессмыслица. Так что `update.bat` в них остался навсегда тем, что
  пришёл в архиве.
- **Git нужен и для обновления тоже.** Он забирает свежую версию с GitHub —
  поэтому шаг 2 пропускать нельзя, даже если бота вы ставили из архива. Саму
  библиотеку BULK установка берёт из папки бота, но `install.bat` всё равно
  проверяет, что git стоит.

## Если не запускается

**«python не является внутренней или внешней командой»**
Python поставлен без галочки «Add to PATH». Переустановите с ней.

**«Not installed yet. Run install.bat first»**
Не выполнен шаг 3, либо `install.bat` запускали не из папки бота.

**«This needs 64-bit Python 3.12 or newer»**
Python слишком старый или 32-битный. Поставьте новый (шаг 1), удалите папку
`app\.venv` и запустите `install.bat` заново — ваших настроек и ключа там нет.

**Установка падает на библиотеке BULK**
Библиотека лежит в `app\vendor` и ставится с диска, так что это редкость.
Если файла там нет — например, папку собирали вручную — установщик идёт за
ней на GitHub, и тогда причина почти всегда в сети: в сообщении будет
`connection` или `timeout`. Проверьте интернет и запустите `install.bat`
заново.

**«no BULK account exists»**
На кошельке ещё нет аккаунта BULK. Внесите USDC на bulk.trade (шаг 5).

**«master ... has no sub-account»**
У одного из мастеров нет саб-аккаунта — нужен у каждого ключа из
`private_key.local`. Создайте: `4. Accounts Management` → `Create New Subaccount`.

**«positions open on accounts no recorded group owns»**
На каком-то аккаунте есть позиция, которую бот не открывал или про которую
забыл (файл состояния стёрт, торговали руками). Он такую позицию никогда бы не
закрыл, поэтому не стартует. Ордера он уже снял. Закройте позиции —
`6. Close All Positions` — и запускайте снова.

**«is not saved as UTF-8»**
`settings.yaml` сохранён не в той кодировке. Блокнот: `Файл` → `Сохранить как`,
«Кодировка» — `UTF-8`.

**«... is not a setting this bot reads»**
Это предупреждение, не остановка: строка в `settings.yaml` написана с ошибкой и
ни на что не влияет. Рядом обычно подсказка `did you mean ...`. Про
`sub1_pubkey` бот пишет, что её можно просто удалить.

**Окно мигает и закрывается**
Запустите файл из `cmd`, чтобы увидеть сообщение: откройте папку, наберите `cmd` в адресной строке проводника, Enter, затем `run.bat`.

**«access denied»**
Эта сборка работает только для аккаунтов, зарегистрированных по реферальной
ссылке или инвайт-коду её владельца. При каждом запуске бот спрашивает об этом
публичный индексер BULK — никаких заранее вписанных списков нет, поэтому новый
аккаунт начинает работать сразу после регистрации по ссылке, без обновления
софта.

Проверяется **master**-аккаунт **первого** ключа в `private_key.local`, а не
саб-аккаунт. Если вы уверены, что заходили по ссылке — проверьте, что первый
ключ в файле именно от того кошелька: адрес печатается в строке лога
`mainnet mode=... master=...` при запуске. Свой статус можно посмотреть
и вручную, открыв в браузере:

```
https://indexer.bulk.trade/v1/aura/wallet/ВАШ_АДРЕС
```

В ответе нужны поля `referred_by_wallet` и `referred_by_code` — если они пустые,
аккаунт зарегистрирован не по той ссылке.

**«could not verify referral»**
Индексер BULK не ответил. Это не отказ в доступе, а невозможность проверить:
подождите и запустите снова. Проверка бывает только при старте, поэтому она не
может прервать уже идущий цикл и не оставит позицию открытой.

**«the affordable size ... is under the $50 minimum the market accepts»**
Нога меньше минимального ордера этого рынка. Если в сообщении сказано
`Nothing was scaled down` — денег хватает, дело в самой цифре: поднимите
`notional_usd` до минимума рынка или выберите пару с порогом пониже. Если же
сказано `Fund the accounts` — тогда действительно не хватает маржи.

**«hold_minutes range runs backwards»**
В диапазоне меньшее число пишется первым: `0.5-1`, не `1-0.5`.

**Тесты пишут «No module named pytest»**
Так и задумано: инструменты разработчика не ставятся, запускающему бота они не
нужны. Команда для установки печатается тут же.

## Как стереть свои данные с компьютера

`4. Accounts Management` → `5. Erase Local Data`. Показывает, что именно лежит
и сколько занимает, и даёт удалить по отдельности:

| | |
|---|---|
| `1. Trading state` | что бот держит открытым, и записанные остановки |
| `2. Private key` | **стирает ключ, сам файл остаётся** — с инструкцией, куда вставить новый |
| `3. Build caches` | служебные кэши; в них попадает имя вашего пользователя Windows |
| `4. Logs` | `logs.txt` и его старые копии — там ваши адреса и вся история запусков |
| `5. Settings` | **сбрасывает `settings.yaml` к заводским**, а не удаляет: без него бот вообще не стартует |
| `6. Proxy` | стирает адрес прокси из `proxy.local` — в нём обычно пароль |
| `9. All of the above` | всё сразу — папка становится как после свежей установки |

Ничего из этого не касается вашего аккаунта на бирже, позиций и денег —
удаляется только то, что хранится на компьютере.

**На удаление ключа обычного `yes` недостаточно**: нужно набрать `DELETE KEY`.
Если у вас нет второй копии ключа, вы потеряете доступ к аккаунту навсегда и
из любых программ, не только отсюда. Сначала убедитесь, что ключ записан
где-то ещё.

Имейте в виду, что `9` заодно **сбросит ваши настройки** — размеры, плечо,
время удержания вернутся к заводским. После него нужно заново вставить ключ и
поправить `settings.yaml`.

### Чего это стереть не может

Папку `app\.venv` — локальное окружение Python. Бот запущен изнутри неё, а
Windows не даёт программе удалить собственный исполняемый файл. Настроек там
нет, но есть **имя вашего пользователя Windows**: в `pyvenv.cfg`, в скриптах
`activate` и внутри заглушек `pip.exe`.

Меню про это честно пишет отдельной строкой и называет размер. Чтобы убрать и
её: закройте окно бота, удалите папку `app\.venv` вручную, затем запустите
`install.bat` — он соберёт новое окружение.

## Управление через Telegram

Бота можно запускать, останавливать и закрывать с телефона.

1. В Telegram напишите **@BotFather**, отправьте `/newbot` и скопируйте токен.
2. Напишите **@userinfobot**: он пришлёт ваш числовой ID.
3. Откройте чат со своим новым ботом и нажмите **Start**, иначе Telegram не даст ему писать вам.
4. В `settings.yaml` заполните блок `telegram:`: `bot_token` и `user_ids`. Если `settings.yaml` создан до появления этой функции, блока в нём нет. Тогда добавьте в конец файла, без отступа слева:

   ```yaml
   telegram:
     bot_token: "123456789:AAE-ваш-токен"
     user_ids: [123456789]
   ```
5. В меню выберите **Telegram Control** и начальный режим (**1. dry run** или **2. live**, потом его можно переключить кнопкой в Telegram). Окно оставьте открытым: пока оно открыто, бот слушает команды. Пароль от ключа спрашивается один раз, при запуске.

Под чатом появятся кнопки:

- **📊 Status** — ход прогона, а между прогонами позиции и ордера (под ответом есть кнопка 🔄 для обновления)
- **▶️ Run** — запустить прогон с целями из `settings.yaml`. Для другой цели напишите `/run 250k`
- **⏹ Stop** — как клавиша S: снять ордера, позиции оставить
- **🛑 Close all** — закрыть все позиции по рынку (если идёт прогон, сначала остановит его)
- **📜 Log** — последние строки лога (`/log 30` — больше)
- **💰 Accounts** — управление маржой: **⚖️ Balance margin** выравнивает свободную маржу между счетами одного мастера, **⬆️ Collect to master** собирает свободную маржу сабаккаунтов на мастер. Сначала показывается план с суммами, переводы уходят только после кнопки **✅ Send**. Во время прогона недоступно: открытая позиция может опираться на эту маржу. Между разными мастерами биржа переводить не даёт
- **🔁 Live / Dry run** — переключить режим: в LIVE прогоны и закрытие торгуют реальными деньгами, в Dry run ничего не отправляется на биржу. Переход в LIVE подтверждается кнопкой, и переключать можно только когда ничего не выполняется

Run и Close all сначала спрашивают, что именно сейчас произойдёт, с кнопками **Start / Yes** и **Cancel**. Кнопка действует минуту и один раз. Кнопки из старых сообщений не срабатывают. Бот отвечает только ID из `user_ids`, а команды, отправленные, пока окно было закрыто, при запуске игнорируются.

После перезагрузки компьютера или сервера окно нужно открыть заново вручную.

## Установка на Linux-сервер (Ubuntu)

Для сервера, который работает круглые сутки: например, в Токио, рядом с биржей. Рассчитано на Ubuntu 24.04. На ней уже есть подходящий Python 3.12.

**1. Подключиться к серверу.** В Windows 10/11 SSH встроен: `Win + R` → `cmd`, затем:

```
ssh root@IP-СЕРВЕРА
```

(Имя пользователя может быть другим, например `ubuntu`. Его пишет провайдер на странице сервера.)

**2. Поставить git и модуль виртуального окружения Python:**

```
sudo apt update && sudo apt install -y git python3-venv
```

**3. Скачать и установить бота:**

```
git clone https://github.com/MakerBuild/Bulk_trading_bot.git ~/bulk-bot
cd ~/bulk-bot
./install.sh
```

**4. Остановить бота на домашнем компьютере.** Закройте и прогон, и окно Telegram Control. Две копии на одних счетах удваивают хеджи.

**5. Перенести свои файлы с домашнего компьютера.** Выполняйте это в `cmd` на **домашнем** компьютере, из папки бота:

```
scp settings.yaml private_key.local root@IP-СЕРВЕРА:~/bulk-bot/
scp app\state\strategy_state.json root@IP-СЕРВЕРА:~/bulk-bot/app/state/
```

Затем на сервере закройте эти файлы от других пользователей:

```
cd ~/bulk-bot && chmod 600 settings.yaml private_key.local
```

`proxy.local` из Японии не нужен.

**6. Проверить:**

```
./run.sh status
```

Должны появиться ваши счета и позиции. Потом `./run.sh` → **8. Telegram Control** → **1. dry run**. В Telegram нажмите **▶️ Run** → **Start** (прогон всухую), потом **⏹ Stop**. Выйти из режима: `Ctrl+C`.

**7. Чтобы бот сам поднимался после перезагрузки сервера:**

```
sudo ./service.sh install
```

Скрипт спросит пароль от ключа и начальный режим (LIVE или dry run), затем запустит Telegram-управление как службу. Служба только слушает Telegram, прогон начинается лишь по кнопке Run. Пароль хранится в `/etc/bulkdn/bulkdn.env`: этот файл может читать только root, но пароль всё равно лежит на сервере. Поэтому держите на этом сервере только тот ключ и те деньги, которые нужны боту.

- `./service.sh status` — работает ли;
- `./service.sh logs` — вывод в реальном времени (`Ctrl+C`, чтобы выйти);
- `sudo ./service.sh uninstall` — убрать службу и удалить сохранённый пароль.

Пока служба работает, не запускайте `./run.sh telegram` вручную: две копии будут бороться за одного Telegram-бота.

**8. Обновление:**

```
cd ~/bulk-bot && ./update.sh && sudo ./service.sh restart
```

Если перезапустить службу во время прогона, она сначала остановит прогон (снимет ордера) и только потом перезапустится. Открытые позиции останутся. Поэтому обновляйтесь между прогонами.

**Безопасность сервера:**

- В панели провайдера откройте SSH (порт 22) только для своего IP.
- Проверьте часы: `timedatectl` должен показывать `System clock synchronized: yes`.
